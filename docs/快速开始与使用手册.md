# 快速开始与使用手册

本文档面向**运维 / 自用者**,讲清楚两件事:

1. **怎么启动**——源码方式、Docker 方式,以及各自的前置准备;
2. **怎么使用**——从配置账号、建套餐、生成唯一码,到三种取码入口(管理后台 / 取码页 / API)的完整闭环。

> 想了解为什么这样设计(FR-0「杜绝一码多码」等不变量),见 `docs/邮箱接码服务.md`;本文只讲操作。

---

## 一、启动前必读:它需要什么

| 依赖 | 说明 |
|---|---|
| **Node ≥ 20** | 源码运行所需(ESM 工程)。Docker 方式镜像已内置,无需本机 Node。 |
| **`.env` 配置** | 凭据只存 `.env`(已 gitignore),数据库不落明文。**至少要填 `ADMIN_TOKEN` 和一组账号凭据**,否则后台进不去、也取不了码。 |
| **真实高校邮箱账号** | 登录名 / 登录密码 / IMAP 独立授权码。SWPU 还需 `SWPU_CAPTCHA_API_TOKEN`(登录打码)。 |
| **前端构建产物** | 源码方式需 `npm run web:build` 生成 `web/dist`,否则取码页与管理后台返回 404(API 仍可用)。Docker 已在构建期完成。 |

> **有状态单实例服务**:IMAP 连接、账号锁、排队、租约定时器、SSE 推送都是**进程内内存态**,只能由唯一进程持有,**不可横向扩展**(多实例会引入双占风险)。容量 = 账号数。

## 二、启动方式

### 方式 A:源码运行(开发 / 调试推荐)

```powershell
# 1. 安装依赖
npm install

# 2. 准备配置:复制模板后编辑(见第三节)
Copy-Item .env.example .env

# 3. 建库(幂等,可重复执行,不破坏已有数据)
npm run migrate

# 4. 构建前端(不构建则取码页 / 管理后台 404,仅 API 可用)
npm run web:build

# 5. 启动
npm start          # 生产模式
npm run dev        # 开发模式(node --watch,改代码自动重启)
```

启动成功后:

```powershell
curl http://localhost:8080/healthz
# 返回 { "ok": true, "pool": {...}, "imap": {...}, "queue": 0, "sse": 0 } 即正常
```

### 方式 B:Docker 运行(生产推荐)

镜像在构建期预置隐身浏览器二进制、编译 native 模块、构建前端,开箱即用。

```powershell
# 1. 准备配置(首次)
Copy-Item .env.example .env       # 编辑 .env,填 ADMIN_TOKEN / API_KEY / 账号凭据

# 2. 构建并后台启动(单实例 + 持久化 volume)
docker compose up -d --build

# 3. 验证
curl http://localhost:8080/healthz
docker compose logs -f            # 跟踪启动日志
```

要点(`Dockerfile` / `docker-compose.yml` 已配好,无需改动):

- 端口映射 `8080:8080`;数据卷 `mcs-data → /app/data`(SQLite + 会话缓存,**重启不丢**占用 / 租约 / 配额)。
- `init: true` 回收浏览器子进程;有头登录用 `xvfb-run` 提供虚拟显示。
- 健康检查每 30s 打 `/healthz`;`restart: unless-stopped` 自动拉起。

停止 / 更新 / 清空:

```powershell
docker compose down               # 停止(保留数据卷)
docker compose up -d --build      # 改代码后重建
docker compose down -v            # 连数据卷一起删(慎用,清空 DB)
```

### 辅助命令

```powershell
npm run demo:swpu      # 单账号 Provider 自检(连真账号:登录→设别名→IMAP 收码→打印邮件)
npm test               # 全量单测 / 集成 / 竞态
npm run test:race      # 仅跑 FR-0 竞态用例
npm run lint           # eslint + prettier 检查(提交前必跑)
npm run format         # prettier 全量格式化
```

## 三、配置 `.env`(最常用项)

凭据**仅存 `.env`**,数据库只存「前缀引用」,日志全链路脱敏。完整项见 `.env.example`。

| 变量 | 必填 | 说明 |
|---|---|---|
| `PORT` | | 服务端口,默认 `8080` |
| `SESSION_DATA_DIR` | | 运行态目录(SQLite + 会话缓存),默认 `./data` |
| `ADMIN_TOKEN` | ✅ | **管理后台密钥**。留空则 `/api/admin/*` 一律返回 `503`(未启用) |
| `API_KEY` | | **自用 API 密钥**。留空则 `/api/v1/*` 一律返回 `503`(未启用) |
| `SWPU_ACCT_1_NAME` | ✅ | 账号登录名(完整邮箱,如 `2020xxxx@swpu.edu.cn`) |
| `SWPU_ACCT_1_PASS` | ✅ | 登录密码 |
| `SWPU_ACCT_1_IMAP_PASS` | ✅ | **IMAP 独立授权码**(非登录密码) |
| `SWPU_ACCT_1_GROUP` | ✅ | 账号分组(如 `swpu`),套餐据此匹配账号 |
| `SWPU_CAPTCHA_API_TOKEN` | ✅(SWPU) | 登录图形验证码打码 token |
| `IMAP_HOST` / `IMAP_PORT` | | 收码 IMAP,默认 `mailgate.swpu.edu.cn:993` |
| `LEASE_TTL_SEC` | | 租约「无码」上限,默认 `900`(15 分钟) |
| `QUEUE_TIMEOUT_SEC` | | 排队兜底上限,默认 `1800`(30min);超此仍未轮到转 `rejected`,产品上不设硬超时 |
| `RETENTION_SEC` | | 成功收码后回看保留期,默认 `604800`(7 天) |
| `RATE_LIMIT_ACTIVATE_MAX` / `_WINDOW_SEC` | | activate 限流:单 `code+IP` 窗口内最大次数 / 窗口秒数 |
| `WEBHOOK_SECRET` / `_TIMEOUT_MS` / `_MAX_RETRIES` | | 自用 API webhook 的 HMAC 签名 / 超时 / 重试 |

**多账号**:用编号后缀复制一组,如 `SWPU_ACCT_2_NAME`、`SWPU_ACCT_2_PASS`…

> ⚠️ **账号凭据存放规则(重要)**:数据库 `email_account.creds_ref` 存的是 **`.env` 变量前缀**(如 `SWPU_ACCT_1`),运行时据此读取 `SWPU_ACCT_1_NAME/_PASS/_IMAP_PASS/_GROUP`。所以**新增账号前,必须先把该账号凭据写进 `.env`**。

## 四、三个入口与鉴权

所有响应统一为 `{ errCode, errMsg, data }`:成功 `errCode: 0`,失败 `errCode` 为字符串错误码。

| 入口 | 路径 | 鉴权 | 未配置密钥 | 密钥错误 |
|---|---|---|---|---|
| **管理后台**(配账号 / 套餐 / 码) | 页面 `/admin`,API `/api/admin` | `Authorization: Bearer <ADMIN_TOKEN>` | `503 ADMIN_DISABLED` | `401 UNAUTHORIZED` |
| **取码页**(付费用户) | `/r/<唯一码>` | 无(凭唯一码本身) | — | — |
| **公开取码 API** | `/api/public` | 无 | — | — |
| **自用 API**(内部脚本) | `/api/v1` | `X-API-Key: <API_KEY>` | `503 API_DISABLED` | `401 UNAUTHORIZED` |

> 密钥比较使用定长安全比较(防时序侧信道)。留空密钥被视为「该入口未启用」,而非「放行任何人」。

## 五、从零到可取码:管理员完整流程

下面示例假设 `ADMIN_TOKEN=local-dev-admin`,服务跑在 `localhost:8080`。两种操作方式任选:**浏览器打开 `/admin`(图形化)** 或 **直接调 API**。

### 步骤 0:进入管理后台(图形化)

浏览器打开 `http://localhost:8080/admin` → 输入 `ADMIN_TOKEN` → 进入。后台分四块:仪表盘(Dashboard)、账号(Accounts)、套餐(Plans)、唯一码(Codes)。下面同时给出对应的 API 调用。

### 步骤 1:在 `.env` 配好凭据,再新增账号

确认 `.env` 已有该账号的四个变量(见第三节),然后新增账号,`credsRef` 填**前缀**:

```powershell
curl -X POST http://localhost:8080/api/admin/accounts `
  -H "Authorization: Bearer local-dev-admin" `
  -H "Content-Type: application/json" `
  -d '{
    "id": "swpu-1",
    "university": "西南石油大学",
    "domain": "swpu.edu.cn",
    "group": "swpu",
    "credsRef": "SWPU_ACCT_1"
  }'
```

**新增即热生效**:自动注册 provider 入池,无需重启;IMAP 在首次取码(绑定租约)时**按需建连**,不常驻。

其它账号管理:

```powershell
curl http://localhost:8080/api/admin/accounts -H "Authorization: Bearer local-dev-admin"            # 列表(脱敏,含健康度)
curl -X POST http://localhost:8080/api/admin/accounts/swpu-1/disable -H "Authorization: Bearer local-dev-admin"  # 禁用
curl -X POST http://localhost:8080/api/admin/accounts/swpu-1/enable  -H "Authorization: Bearer local-dev-admin"  # 启用
curl -X POST http://localhost:8080/api/admin/accounts/swpu-1/relogin -H "Authorization: Bearer local-dev-admin"  # 强制重登
```

### 步骤 2:创建套餐(前缀 = 一套约束)

`allowedGroups` 必须与账号 `group` 匹配,套餐才能选到该账号。`POST` 为 upsert(同前缀覆盖)。

```powershell
curl -X POST http://localhost:8080/api/admin/plans `
  -H "Authorization: Bearer local-dev-admin" `
  -H "Content-Type: application/json" `
  -d '{
    "prefix": "gh",
    "name": "GitHub 注册码",
    "allowedGroups": ["swpu"],
    "targetSenders": ["@github.com"],
    "codeRegex": "\\b\\d{4,8}\\b",
    "quota": 1,
    "leaseTtlSec": 900,
    "retentionSec": 604800,
    "maxRenews": 5,
    "enabled": true
  }'
```

| 字段 | 含义 |
|---|---|
| `prefix` | 套餐前缀,唯一码形如 `<prefix>-<32位hex>` |
| `name` | 套餐显示名 |
| `allowedGroups` | 允许使用的账号分组 |
| `targetSenders` | 收码发件人(域名 / 通配) |
| `codeRegex` | 验证码提取正则(可选便利字段) |
| `quota` | 该唯一码成功收码次数 |
| `leaseTtlSec` | 无码超时(覆盖全局默认) |
| `retentionSec` | 回看保留期 |
| `maxRenews` | 最大重申请次数 |
| `enabled` | 是否启用 |

### 步骤 3:批量生成唯一码

```powershell
curl -X POST http://localhost:8080/api/admin/codes `
  -H "Authorization: Bearer local-dev-admin" `
  -H "Content-Type: application/json" `
  -d '{ "prefix": "gh", "count": 10 }'
# → { "errCode":0, "data": { "count":10, "codes":["gh-3f9a…","gh-7c2b…", …] } }
```

唯一码形如 `gh-<32位hex>`(128bit 随机,不可枚举),`status=unused`、**永久有效**(直到首次成功收码才开始回看倒计时)。

按状态查询 / 吊销:

```powershell
curl "http://localhost:8080/api/admin/codes?status=unused" -H "Authorization: Bearer local-dev-admin"
curl -X POST http://localhost:8080/api/admin/codes/gh-3f9a.../revoke -H "Authorization: Bearer local-dev-admin"
```

### 步骤 4:发放与取码

把链接 **`http://<host>:8080/r/<唯一码>`**(如 `/r/gh-3f9a…`)发给用户:

1. 用户打开页面 → 点「申请邮箱」(此刻才占用账号);
2. 页面显示分配的**别名邮箱**与倒计时;
3. 用户拿别名去第三方注册;
4. 邮件到达 → SSE 实时回显整封邮件(含提取的验证码)。

### 步骤 5:监控

仪表盘页或:

```powershell
curl http://localhost:8080/api/admin/stats -H "Authorization: Bearer local-dev-admin"
# → 池水位 free/leased/unhealthy、排队数、SSE 连接数、各状态租约数
```

## 六、API 参考

### 公开入口 `/api/public`(无需鉴权,供取码页/付费用户)

| 方法 | 路径 | 请求 | 说明 |
|---|---|---|---|
| POST | `/activate` | `{ "code": "gh-…" }` | 申请邮箱:分流 `active`(含 `alias`/`expiresAt`)或 `used` 回看;失效返回错误码 |
| GET | `/leases/:id` | — | 轮询租约状态 |
| GET | `/leases/:id/stream` | — | **SSE** 实时推送:`message`(状态)/ `done`(终态,附整封邮件);已终态重连返回 `204` |
| POST | `/leases/:id/renew` | — | 超时后重申请(受 `maxRenews` 限制) |
| POST | `/leases/:id/cancel` | — | 提前释放 |
| GET | `/codes/:code/results` | — | 收码结果回看(保留期内的整封历史邮件) |

### 自用 API `/api/v1`(`X-API-Key`)

直接按套餐取码,内部即时签发临时码走同一闭环(复用全部安全护栏)。

```powershell
# 申请:返回别名 + 到期时间(可选 callbackUrl 做 webhook 回调)
curl -X POST http://localhost:8080/api/v1/leases `
  -H "X-API-Key: <API_KEY>" `
  -H "Content-Type: application/json" `
  -d '{ "plan": "gh", "callbackUrl": "https://your.app/hook" }'
# → { "data": { "leaseId":"…", "alias":"xxx@swpu.edu.cn", "expiresAt":169…, "code":"gh-…" } }

# 取码:received 时 data 含整封 mail(from/to/subject/date/text/html)+ 便利 code
curl http://localhost:8080/api/v1/leases/<leaseId> -H "X-API-Key: <API_KEY>"

# 提前释放
curl -X DELETE http://localhost:8080/api/v1/leases/<leaseId> -H "X-API-Key: <API_KEY>"
```

### 常见错误码

| 错误码 | HTTP | 含义 |
|---|---|---|
| `CODE_NOT_FOUND` | 404 | 唯一码不存在 |
| `CODE_EXPIRED` | 410 | 回看期满 |
| `CODE_EXHAUSTED` | 409 | 配额耗尽 |
| `CODE_REVOKED` | — | 已吊销 |
| `PLAN_DISABLED` | — | 套餐停用 / 不存在 |
| `POOL_BUSY` | 503 | 池满排队超时 |
| `LEASE_NOT_FOUND` | — | 租约不存在 |
| `LEASE_NOT_TERMINAL` | — | 非终态不能 renew |
| `RENEW_LIMIT` | — | 超重申请上限 |
| `ADMIN_DISABLED` / `API_DISABLED` | 503 | 对应入口未配置密钥 |
| `UNAUTHORIZED` | 401 | 密钥错误 |

## 七、取码闭环(数据流速览)

```
activate(唯一码)
  → AccessService 校验分流
  → AccountPool 取空闲账号(或排队)
  → provider.setAlias(唯一别名)
  → 建 active 租约
  → ReceiverHub 按需连 IMAP + 绑定收码 + 起超时定时器
  → IMAP 命中邮件(To + From + 时间窗)
  → 原子交付(active→received + 扣配额)
  → 释放账号(后台断 IMAP)
  → SSE / webhook 推送整封邮件
  └─(15min 无码)→ expired → 释放 → 可 renew
```

## 八、常见问题排查

| 现象 | 可能原因 / 处理 |
|---|---|
| 打开 `/admin` 或 `/r/...` 是 404 | 前端未构建。源码方式执行 `npm run web:build` 后重启。 |
| 后台输入密钥提示「管理后台未启用」 | `.env` 的 `ADMIN_TOKEN` 为空。填上固定值后重启。 |
| `/api/v1/*` 返回 `503 API_DISABLED` | `.env` 的 `API_KEY` 为空,自用 API 未启用。 |
| 新增账号后取不到码 / 登录失败 | 检查 `.env` 里 `credsRef` 对应的四个变量是否齐全;`SWPU_CAPTCHA_API_TOKEN` 是否有效;用 `/relogin` 强制重登或看日志。 |
| `activate` 返回 `POOL_BUSY` | 账号都被占用且排队超时。容量 = 账号数,可增配账号(先写 `.env` 再新增)。 |
| 重启后占用 / 租约丢失 | 确认 `SESSION_DATA_DIR`(Docker 为 `mcs-data` 卷)持久化正常,未被 `docker compose down -v` 清空。 |
| 收不到码但邮件确实到了 | 检查套餐 `targetSenders` 是否匹配真实发件人;时间窗 / 别名是否正确。可 `npm run demo:swpu` 单账号自检链路。 |
