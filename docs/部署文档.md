# mail-code-service · 生产部署文档

面向域名 **19880321.xyz**、服务器 **118.89.134.75**（腾讯云）的完整上线流程。

## 架构总览

```
                    ┌───────────────────── 服务器 118.89.134.75 ─────────────────────┐
   用户 / 浏览器      │                                                                │
   https://19880321 ─┼─► Nginx(宿主机)  ──TLS 终止 + 反代──►  App 容器(127.0.0.1:8080) │
        .xyz         │   :80 → 跳 :443                          docker compose         │
                    │   :443 ssl                               data volume(SQLite)    │
                    │      ▲                                                            │
   Let's Encrypt ───┼──────┘  acme.sh 自动续期(HTTP-01 + cron，60 天自动续 + reload)   │
                    └────────────────────────────────────────────────────────────────┘
```

**要点**
- App 容器**只绑 `127.0.0.1:8080`**，不直接暴露公网；唯一入口是宿主机 Nginx（TLS 终止）。
- Nginx 已为 **SSE**（收码实时推送）关闭缓冲、拉长读超时——这是本服务的关键，否则前端收不到实时邮件。
- 证书用 **acme.sh + Let's Encrypt HTTP-01**，装宿主机自动续期，**免 API Token**。

**前置条件（先在腾讯云控制台完成）**
1. 域名 **19880321.xyz** 添加 **A 记录 → 118.89.134.75**（DNSPod 控制台，解析生效后 `ping 19880321.xyz` 应指向该 IP）。
2. 服务器**安全组放行** TCP **22 / 80 / 443**。
3. 已有一个可登录服务器的账号（下文以 `root` 为例；非 root 需能 `sudo`）。

验证免密：

## Step 4 · 服务器：拉取代码 + 配置 .env

### 4.1 配置 GitHub Deploy Key（私有仓库拉取）

```bash
# 服务器上生成部署专用密钥
ssh-keygen -t ed25519 -C "deploy@19880321" -f ~/.ssh/id_ed25519 -N ""
cat ~/.ssh/id_ed25519.pub
```

复制输出的公钥 → GitHub 仓库 **Settings → Deploy keys → Add deploy key**（只读即可）。然后：

```bash
mkdir -p /opt && cd /opt
git clone git@github.com:laiyangde/mail-code-service.git
cd mail-code-service
git checkout feature/queue-confirm-admin
```

### 4.2 配置生产 .env（**独立于本地，密钥全部重新生成**）

```bash
cd /opt/mail-code-service
cp .env.example .env
```

编辑 `.env`（`vim .env`），**必改项**：

| 变量 | 生产值 | 说明 |
|---|---|---|
| `CODE_SIGNING_SECRET` | `openssl rand -hex 32` 的输出 | **唯一码签名密钥，一经上线不可改**（改则历史码全失效） |
| `ADMIN_TOKEN` | `openssl rand -hex 32` 的输出 | 管理后台密钥，务必强随机（勿用示例值） |
| `API_KEY` | `openssl rand -hex 32` 的输出 | 自用 API 密钥（不用自用 API 可留空=禁用） |
| `TRUST_PROXY` | `172.16.0.0/12` | 信任 Docker 网段的反代头，限流按真实 IP。App 仅绑 127.0.0.1，公网无法伪造 |
| `SWPU_ACCT_1_NAME` / `_PASS` / `_IMAP_PASS` | 真实账号凭据 | 邮箱账号（明文只存此文件，不入库） |
| `SWPU_CAPTCHA_API_TOKEN` | 打码平台 token | 登录用 |

一条命令生成三个强随机密钥（复制进 .env）：

```bash
for k in CODE_SIGNING_SECRET ADMIN_TOKEN API_KEY; do echo "$k=$(openssl rand -hex 32)"; done
```

> ⚠️ `.env` 已在 `.gitignore` 中，不会被提交。请**离线备份** `CODE_SIGNING_SECRET`（丢失=所有已发码失效）。

## Step 5 · 服务器：启动 App 容器

```bash
cd /opt/mail-code-service
docker compose up -d --build      # 首次构建较久（含前端构建 + Chromium 预置）
docker compose ps                 # STATUS 应为 healthy
curl -fsS http://127.0.0.1:8080/healthz && echo   # {"ok":true,...}
```

若健康检查失败：`docker compose logs --tail=100`。常见是 `.env` 缺 `CODE_SIGNING_SECRET`（会 fail-fast 拒绝启动，日志有明确提示）。

## Step 6 · 服务器：Nginx + SSL 证书（含自动续期）

### 6.1 先用引导配置跑通 HTTP（为签证书铺路）

```bash
# ACME 挑战目录
mkdir -p /var/www/acme

# 启用"仅 80"的引导配置
ln -sf /opt/mail-code-service/nginx/bootstrap-http.conf /etc/nginx/conf.d/19880321.xyz.conf
rm -f /etc/nginx/sites-enabled/default 2>/dev/null || true   # 去掉默认站点（如有）
nginx -t && systemctl reload nginx

# 此时可先验证反代通不通（应返回 App 首页或 JSON）
curl -I http://19880321.xyz
```

### 6.2 安装 acme.sh 并签发证书（HTTP-01）

```bash
# 安装 acme.sh（自带 cron 自动续期机制）
curl https://get.acme.sh | sh -s email=你的邮箱@example.com
source ~/.bashrc

# 用 Let's Encrypt 作为 CA（免 ZeroSSL 注册）
~/.acme.sh/acme.sh --set-default-ca --server letsencrypt

# 通过 webroot 签发（EC 证书）
~/.acme.sh/acme.sh --issue -d 19880321.xyz -w /var/www/acme --keylength ec-256
```

### 6.3 安装证书到 Nginx（并登记续期后自动 reload）

```bash
mkdir -p /etc/nginx/ssl/19880321.xyz

~/.acme.sh/acme.sh --install-cert -d 19880321.xyz --ecc \
  --key-file       /etc/nginx/ssl/19880321.xyz/key.pem \
  --fullchain-file /etc/nginx/ssl/19880321.xyz/fullchain.pem \
  --reloadcmd      "systemctl reload nginx"
```

> `--install-cert` 会记住 `--reloadcmd`：**每次自动续期后自动重载 Nginx**，无需人工干预。

### 6.4 切换到完整配置（启用 443）

```bash
ln -sf /opt/mail-code-service/nginx/19880321.xyz.conf /etc/nginx/conf.d/19880321.xyz.conf
nginx -t && systemctl reload nginx
```

### 6.5 验证自动续期机制

```bash
~/.acme.sh/acme.sh --list           # 看到域名与到期日
crontab -l | grep acme.sh           # 存在每日检查任务（证书 <60 天时自动续 + reload）
~/.acme.sh/acme.sh --renew -d 19880321.xyz --ecc --force   # 可选：手动强制续一次，确认链路通
```

**续期原理**：acme.sh 安装时写入 crontab，每天检查一次；证书剩余有效期 < 60 天时自动续签，并执行登记的 `reloadcmd` 重载 Nginx。**全自动，无需再管**。

```bash

echo | openssl s_client -connect 19880321.xyz:443 -servername 19880321.xyz 2>/dev/null | openssl x509 -noout -dates

# 2. 健康检查（经 Nginx）
curl -s https://19880321.xyz/healthz

# 3. HTTP 自动跳 HTTPS
curl -I http://19880321.xyz    # 应 301 → https
```

**功能验证**（浏览器）
1. 管理后台：`https://19880321.xyz/admin` → 输入 `ADMIN_TOKEN` → 新增账号 / 套餐 / 生成唯一码。
2. 取码页：`https://19880321.xyz/<唯一码>` → 申请邮箱 → 确认已发送 → **SSE 实时回显整封邮件**（若卡在"监听中"不出邮件，多半是 Nginx 缓冲没关，见故障排查）。

## 故障排查

| 现象 | 排查 |
|---|---|
| `502 Bad Gateway` | App 没起或没绑 127.0.0.1:8080。`docker compose ps` / `curl http://127.0.0.1:8080/healthz` |
| SSE 卡住、收不到实时邮件 | Nginx 缓冲没关。确认用的是 `19880321.xyz.conf`（含 `proxy_buffering off`），`nginx -t && systemctl reload nginx` |
| 限流误伤（正常用户 429） | `TRUST_PROXY` 没配或不匹配 Docker 网段。`docker network inspect mail-code-service_default` 查网关，确保落在 `172.16.0.0/12`；改 `.env` 后 `docker compose up -d` |
| 证书签发失败 | 80 端口未放行 / A 记录未生效 / `/var/www/acme` 不可写。`curl http://19880321.xyz/.well-known/acme-challenge/test` 应能被 Nginx 处理 |
| `nginx -t` 报证书文件不存在 | 还没签发就启用了 443 配置。先回到 §6.1 引导配置，签发后再切完整配置 |
| App 启动即退出 | `.env` 缺 `CODE_SIGNING_SECRET`（fail-fast）。日志会明确提示 |

## 附录 B · SSL 备选：DNS-01（80 端口被封 / 需泛域名时）

腾讯云 DNS 即 DNSPod。到 [DNSPod 控制台](https://console.dnspod.cn/) → 用户中心 → API 密钥，创建得到 `DP_Id` 与 `DP_Key`：

```bash
export DP_Id="你的ID"; export DP_Key="你的Key"
~/.acme.sh/acme.sh --issue --dns dns_dp -d 19880321.xyz --keylength ec-256
# 之后 install-cert 同 §6.3（DNS 方式续期同样全自动，且无需开放 80）
```

## 附录 C · 备选：Nginx 也容器化（一体化 compose）

若不想在宿主机装 Nginx，可加一个 nginx 服务到 `docker-compose.yml`（挂载 `nginx/` 配置与证书目录，`ports: 80:80, 443:443`），App 端口改回容器内网络、`proxy_pass http://mail-code-service:8080`。证书续期建议仍用宿主机 acme.sh 签发后挂载进容器，reloadcmd 用 `docker exec <nginx容器> nginx -s reload`。宿主机 Nginx 方案续期更省心，故默认推荐前者。
